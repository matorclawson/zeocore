bump: minor
**Two distributions registering the same integration name is now an error that names each of them, never "the last one wins" (zeocore-SOW-36 slice 1).** The loader (and `load_integrations`, which calls it) refuses an ambiguous name in strict and non-strict mode; `list_available_entry_points` lists one row per registration with the `distribution` and `ambiguous` fields; the load report gains `id_mismatches`, a report-only list of names whose instance `integration_id` differs (google.mail -> googlemail), which is never an error and renames nothing. Limit: `importlib.metadata` collapses two copies of one normalised distribution name before the guard sees them. Rolling back below this release removes the guard.

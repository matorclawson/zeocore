**`intervention_card`: one closed card for an operator situation.** `zeo_core.contracts.ui.intervention_cards` adds the payload for a work location, checkpoint, blocker, decision, request status, outcome, project checkpoint or read-only source item, chosen by `situation`. It carries data and typed action ids only: no intervention state, no authority, no computed age or lateness. Optional keys are absent, never null. It is registered as the fifth `widget.upsert` component of Core's own profile; the four locked briefing components stay byte-compatible (`LOCKED_COMPONENTS`), and the locked schema still refuses the new name. `contracts/zeocore-v1/ui.widget-upsert.schema.json` lists the fifth name.

The payload is published for front ends: `contracts/zeocore-v1/ui.intervention-card.schema.json` (`zeocore schema ui.intervention-card`) and TypeScript types generated from it, `contracts/zeocore-v1/ui.intervention-card.d.ts`. Both are checked against the model, so they cannot drift. The valid fixtures under `tests/test_contracts/fixtures/intervention_cards/valid` are examples of every situation.

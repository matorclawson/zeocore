**kit: update, rollback and recover act on what they see, and never touch protected or live state by guess.** The council's review of slice 3 found that `recover` stopped and switched a healthy service without first proving it was already running; it now proves the current version as it stands and clears the record, and acts (under the live rule and its fence) only if that fails. The live rule fails closed when `Status` cannot answer. `Guard` and the install-root check resolve symbolic links and want absolute paths; a snapshot of the protected paths is compared before the switch and after the proof, so any hook that touched one ends the operation (appending to append-only state is allowed). An `apply` leaves an intent, so a half-done one blocks later changes until `recover` reads the targets. State renames sync their directory. Hook errors and intent fields are folded to one line in text mode; a lock failure is `failed`, not `busy`; `update --check` writes nothing; stale install directories are swept.

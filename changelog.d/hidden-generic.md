**BREAKING for the newsletter path: the converter no longer evaluates CSS to hide text; it reports instead (zeocore-SOW-41).** `convert_newsletter` and `convert_decoded_message` now drop only what the HTML itself marks not rendered: the `hidden` attribute and an element's own inline `display:none` or `visibility:hidden`/`collapse`. Text that depended on CSS (class and id rules, selectors, `@media`, `opacity`, `font-size:0`, zero or maximum sizes, off-screen offsets, `clip`, colour on colour, an over-long `style`) is now KEPT, and the new required field `ConvertedItem.diagnostics` says what was present and not evaluated (every key always present). This reverses the whitelist merged in #146: an unrelated stylesheet rule no longer changes whether an element is dropped (fixes held originals with `hidden_max_size`). `stripped` keeps `hidden`, `hidden_attribute`, `hidden_display`, `hidden_visibility` and `style_oversize`; the keys `hidden_opacity`, `hidden_font_size`, `hidden_max_size`, `hidden_zero_size`, `hidden_offscreen`, `hidden_clip`, `hidden_mso`, `hidden_color_match`, `hidden_style_class` and `hidden_oversize` are gone, and `ConvertedItem` gains the required `diagnostics` argument. Callers must handle non-zero diagnostics (hidden preheader text can now reach the Markdown). The cleaner version is `newsletter-clean-2`. Other behaviour changes: a `style` attribute over 4096 characters used to be dropped as hidden and is now kept and counted (`style_oversize`, `inline_style_unparsed`); an element whose `style` holds a comment or an escape is no longer decided and is counted; an element with a later `display` or `visibility` value the converter does not know is kept and counted; precedence in a `style` attribute now honours `!important` and this also changes tracking-pixel detection (`width:1px!important;width:50px` is a pixel; `width:1px;width:50px` is not). A `display` or `visibility` declaration whose value is not a plain keyword (`var()`, `env()`), anywhere among the declarations, is kept and counted. Tracker, footer and per-recipient-parameter cleaning is unchanged. **Condition for consumers (council, condition 3):** the newsletter path must not adopt this release until the application holds items whose diagnostics are non-zero (dt-library keeps its hash-locked 0.25.2 until then); without that, hidden preheader and tracking text reaches the issue silently. Strings in a `style` attribute are not tokenised (a documented limit).

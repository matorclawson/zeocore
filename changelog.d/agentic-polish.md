**The `zeocore` command no longer waits on stdin it will refuse, and says why it refused.** A usage error (a missing schema name, a bad flag, an unknown `release` verb) now answers at once, before stdin is read, even when stdin never closes; a terminal on stdin reads as empty. An unknown schema name is its own refusal ("no such schema; run zeocore schema list") and never echoed. Stdin that isn't strict JSON carries a `reason` (`empty`, `too_large`, `not_utf8`, `syntax`, `duplicate_key`, `non_finite_number`, `too_deep`, `outside_canonical_domain`, or `not_an_object`) and a fix. A value that fails its contract points at `zeocore schema <name>`. `help --json` names `zeocore schema list`, and `AGENTS.md` gains a worked example, the exit-20 rule and the honest Broker steps.

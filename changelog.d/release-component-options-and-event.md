The release-on-merge component can now serve repositories that are not Python packages on PyPI. The version script is a file, `.github/release/plan.py`, that a runner outside GitHub Actions can run as it stands (the workflow keeps an identical inline copy, and a test fails if they differ). It takes a tag namespace (`tag_prefix`, default `v`) and an index setting (`index`, default PyPI, or `none`), and it prints the tag it computed. Each GitHub Release now carries a `release-event.json` (schema `zeo.release-event/v1`) that names the version, tag, commit, tree, the notes' digest and every released file's digest, and ends with a digest of itself. `.github/release/README.md` lists the executor's files, its options and how a private repository runs it. Nothing changes for zeocore's own releases. Tests also pin that the component takes no version, commit or ref, and that only the docs site can be started by hand.

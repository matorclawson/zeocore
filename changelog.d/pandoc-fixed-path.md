**The newsletter converter: a pinned pandoc, and a narrower hidden-text rule.** `convert_newsletter` and `convert_decoded_message` take `pandoc_path` and `expected_pandoc_sha256` (an absolute path and a digest; no `PATH` lookup; a relative path is `pandoc_missing`, another digest `renderer_mismatch`). The hidden-text filter now follows the council's ruling zc-dtl-webkit-b312-v1: `max-height:0`/`max-width:0` hides only a box that clips (`overflow:hidden` or `clip`) and is not inline, and `mso-hide:all` alone is no longer hidden, because browsers paint both. The same follows for the other CSS hiding techniques that browsers ignore without their condition (the council's follow-up to that ruling, eight WebKit counterexamples): `width:0`/`height:0` need a clipping, non-inline box (`line-height:0` alone never hides), a negative `left`/`top` needs `position:absolute` or `fixed`, a negative `text-indent` needs a non-inline element, `clip` needs a positioned element, and `max-height`/`max-width` never hide a table cell, row or row group. The noise data file's version is 2026-10-18, so a stored item's `converter` says which rule produced it.

bump: minor

A signing manifest can take its digests from a reviewed build inventory instead of having them written into `release.yaml` for every release. With `pins: inventory` in the `signing` section the manifest keeps the reviewed structure only, and the digests come from a `zeo.build-inventory/v1` file that goes through an ordinary pull request (`release/inventory/<version>.json`). The signing service admits the inventory only when the commit is merged to the default branch, holds exactly those bytes at the named path, and carries a `council/approve` status created by the adopted approver (otherwise `inventory_unreviewed`, or `review_unreadable` when GitHub cannot be read). `zeocore release sign`, `verify`, `receive` and `pack` take an optional `inventory` (and `pack` an `inventory_path`); a request without them is unchanged byte for byte. A refusing port, `zeo_core.release.signing.event_auth`, is added for authenticating the release event after the seal: it checks that the seal verified, that the event is the unchanged canonical document and that what was authenticated is exactly its payload, and holds until a mechanism for a JSON payload is adopted. Manifests that pin their own digests are not affected.

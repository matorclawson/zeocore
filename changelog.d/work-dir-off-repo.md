**`ZEO_WORK_DIR` keeps a checkout's environment and output off the repository.** With it set, `make` puts the virtual environment, the docs site, build output, coverage data and the pytest, mypy, ruff and bytecode caches under `$ZEO_WORK_DIR/<checkout directory name>-<hash of its path>/` (so two checkouts with one name, such as worktrees, never share an environment), and the checkout holds only the repository and `.import_linter_cache`. This is the org's rule from the operator, 2026-10-12: repositories on one volume, CI and local runs on another. Unset, nothing changes: everything stays inside the checkout, as for any contributor and in CI. Example: `make setup ZEO_WORK_DIR=/Volumes/ZeoWork/zeocore`, or export it in the session's environment so the pre-push hook's `make verify` uses it too.
`ZEO_WORK_DIR` must be one absolute path outside the checkout; `make` refuses a relative path, a path with spaces, and the checkout itself or anything below it.
